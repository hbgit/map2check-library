# Release process

A release publishes one archive per target with the generated C header,
two static libraries, the 21 bitcode modules of the drop-in runtime, the
validated Map2Check commit, an inner checksum file, the integration guide
and the compatibility docs. `scripts/package-release.sh` builds it, and CI
runs the same script on every push through
`scripts/test-package-release.sh`.

## Archive layout

`dist/map2check-library-<version>-<target>.tar.gz`, where `<version>` comes
from `Cargo.toml` and `<target>` is the `rustc` host triple (for example
`x86_64-unknown-linux-gnu`):

| Path in the archive | Source |
|---|---|
| `include/map2check.h` | Generated by `build.rs`; `MAP2CHECK_VERSION` must equal `<version>`. |
| `lib/libmap2check.a` | `cargo build --release` (no features). |
| `lib/<Module>.bc` (21 files) | `scripts/build-runtime-bc.sh`: exactly the modules `Caller::linkLLVM` links, no others (list in `docs/cutover/d7-layout.md`). |
| `MAP2CHECK_VERSION` | Copy of `vendor/MAP2CHECK_VERSION`: the Map2Check `develop` commit the runtime was validated against. |
| `SHA256SUMS` | Inside the archive: `sha256sum` of every other file, relative paths. |
| `lib/libmap2check_runtime.a` | `cargo build --profile runtime --features wasm` (unwinding panics and the wasm2c entry points). |
| `docs/integration-guide.md`, `docs/api-deltas.md`, `docs/semantic-deltas.md` | Repository. |
| `CHANGELOG.md`, `LICENSE` | Repository. |

Since 2.0.0 (D6) both libraries export the C runtime ABI of Map2Check
`develop` only (`scripts/check-export-set.sh`); the `libfuzzer` library and
the KLEE runtime bitcode (`scripts/build-klee-runtime.sh`) are gone. The
bitcode modules of the drop-in runtime join the archive in plan Task 3.2.

`dist/SHA256SUMS` sits next to the archive.

## Steps

1. **Version.** On a branch off `develop`, set `version` in
   `Cargo.toml` and the `org.opencontainers.image.version` label in
   `Dockerfile`. `tests/header_version.rs` fails if they disagree.
2. **Changelog.** Move the `[Unreleased]` entries into a new
   `## [<version>] - YYYY-MM-DD` section of `CHANGELOG.md`, and leave an
   empty `[Unreleased]` above it.
3. **Compatibility docs.** Make sure `docs/api-deltas.md` and
   `docs/semantic-deltas.md` reflect every ABI or behaviour change since
   the last release. `cargo test --all-features --test compat_docs` must
   pass.
4. **Pull request.** Open a PR to `develop` and merge it once
   `build_and_test` is green, then open a PR from `develop` to `main`
   (1 review required).
5. **Package.** On the merged commit, run:

   ```sh
   BC_DIR=<dir of the 21 .bc> scripts/package-release.sh   # writes dist/
   (cd dist && sha256sum -c SHA256SUMS)
   ```

6. **Tag.** Create a signed tag on the merged commit and push it:

   ```sh
   git tag -s v<version> -m "map2check-library v<version>"
   git push origin v<version>
   ```

7. **GitHub release.** Attach the archive and checksums. Use
   `--prerelease` for `-rcN` versions:

   ```sh
   V=<version>
   awk -v h="## [$V]" 'index($0,"## [")==1{p=index($0,h)==1;next} p' CHANGELOG.md > dist/notes.md
   gh release create "v$V" dist/map2check-library-"$V"-*.tar.gz dist/SHA256SUMS \
     --title "v$V" --notes-file dist/notes.md \
     --prerelease   # omit for a final (non -rcN) version
   ```

   `dist/notes.md` holds the body of the `## [<version>]` section, up to
   the next `## [` heading or the end of the file. Name the archive by
   version so older archives left in `dist/` are not uploaded;
   `SHA256SUMS` only covers the newest one.

Steps 6 and 7 publish outside the repository; the maintainer runs them.
Process note: push, tag, pull request and release happen only on the
maintainer's explicit request; building the package never does any of them.
