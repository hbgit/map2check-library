# Verify and Resolve GitHub PR #3 Conflicts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the five conflicting paths between `feat/M3_paridade` (PR #3) and its base `feature/rust`, producing a tree that builds, passes the full Rust test suite, and runs all four C ABI programs clean under ASan/UBSan, so that PR #3 reports `MERGEABLE` with green checks.

**Architecture:** Merge `origin/feature/rust` into a local `feat/M3_paridade`. Both branches independently implemented the same three FFI symbols after their merge base `a0f494d` (`map2check_map_non_static_alloca`, `map2check_map_funct_address`, `map2check_check_free_resolved_address`), with incompatible signatures and no shared ancestor for them. The resolution rule, chosen by the maintainer, is: **the base branch's signatures are canonical** (they are what PR #2 already shipped into `feature/rust`), while PR #3's signature-neutral semantics are preserved — `set_malloc()` on the VLA entry, pointer-width `size_destiny` on the function-address entry, `FreeResolvedChecker` for the resolved-free check, and `char` as `i8`. The C test files are then adapted to the canonical signatures, and PR #3's new SV-COMP exports are folded back into the expanded harness.

**Tech Stack:** Rust 1.82.0, Cargo, cbindgen (header generated by `build.rs`), Clang with AddressSanitizer + UndefinedBehaviorSanitizer, Docker, GitHub Actions, `gh` CLI.

**Spec:** GitHub PR #3 (`hbgit/map2check-library#3`, head `feat/M3_paridade` → base `feature/rust`); `docs/api-deltas.md` (PR #3's own record of intentional API decisions); base branch `origin/feature/rust` at `672a84c`.

- The merge commit is authored on `feat/M3_paridade` and pushed to `origin/feat/M3_paridade`.

## Review Focus

The five input classes or failure modes most likely to bite, given the spec's silence. Each is pinned by a test in the task that owns the code.

1. **`char` ABI width after the merge.** `NonDetValue::Char` becomes `i8` while the base's `nondet_ffi!(..., Char, u8, c_char, c)` invocation still casts to `u8`. Taking the base side verbatim is a type mismatch at compile time. Owned by Task 2, pinned by the `map2check_save_nondet_log_char` invocation in Step 3 and by the Rust test suite in Task 5.
2. **Stale hand-written `extern` declarations in `test/*.c`.** `test/codeAPI_by_caller_test.c:16` and `test/codeklee_by_caller_test.c:20` declare a 4-argument `map2check_save_nondet_log_int` that returns `void`; the generated header declares the 5-argument form returning `non_det_log_t *`. Keeping either line is a hard "conflicting types" compile error. Owned by Task 4, pinned by compiling both files in Task 6.
3. **`FreeResolvedChecker` becoming dead code.** `rust/src/ffi.rs:13` imports it (that line auto-merged). Resolving the resolved-free check to the base's `FreeChecker` body leaves both the import and `memtrack::is_invalid_free_resolved` unused, failing `-D warnings`. Owned by Task 2, pinned by `cargo clippy ... -D warnings` in Task 5.
4. **Silent loss of symbol coverage in `tests/ffi_harness.c`.** The base harness covers every symbol PR #3's harness covers **except five**: `get_next_step`, `__VERIFIER_nondet_pointer`, `__VERIFIER_assume`, `__VERIFIER_assert`, `map2check_fuzzer_assume`. Taking the base file wholesale drops PR #3's new exports from the "100% of exported symbols" harness and nothing fails. Owned by Task 3, pinned by Step 6's coverage diff.
5. **Negative sizes on the VLA path.** The merged harness calls `map2check_map_non_static_alloca(NULL, NULL, -1, -1, 5, 1)`. PR #3's implementation has no negative-size guard (the base got one by delegating to `map2check_map_alloca`), so `size as usize` becomes 2^64-1. Owned by Task 2, pinned by the hostile round in Task 6.

/// variable holding a function pointer (e.g. `void (*f)(void) = &foo;`) does

#[no_mangle]
pub unsafe extern "C" fn map2check_map_funct_address(
    var_name: *const std::os::raw::c_char,
    ptr_address: *const std::os::raw::c_void,
) {

        || {
            // SAFETY: caller guarantees var_name is a valid C string or null.

                    addr,

                    false,

                    false,
                ));
